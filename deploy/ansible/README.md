# Deploy (appmire-hetz1)

Deploys the pluvio stack (api + worker + **web PWA**) to the shared
**appmire-hetz1** box, which is already bootstrapped (docker, ufw, nginx,
certbot) by the charging deploy. So this playbook only ships the app and adds an
nginx vhost — no Traefik (the compose `prod` profile is left unused; the host
nginx is the public entry).

The host nginx serves the PWA at `/` (web container, `127.0.0.1:8001`) and keeps
the API **same-origin** under `/v1`, `/healthz`, `/docs` (`127.0.0.1:8000`), so
the browser needs no CORS.

```
cd deploy/ansible
cp secrets.yml.example secrets.yml        # fill in tiles_api_key (gitignored)
ansible-playbook site.yml                 # app (build+run) + vhost + TLS
ansible-playbook site.yml --tags app      # rebuild/redeploy containers only
ansible-playbook site.yml --tags nginx    # vhost / TLS only
```

- Connects as the `ansible` user (key `~/.ssh/id_ed25519`).
- `--tags app` rsyncs `backend/` → `/opt/pluvio-backend` and `web/` → `/opt/web`,
  renders `.env`, and `docker compose up -d --build` (api on `127.0.0.1:8000`,
  worker, web on `127.0.0.1:8001`). The web image injects `VITE_API_BASE` /
  `VITE_TILES_URL` / `VITE_TILES_KEY` into `config.js` at container startup.
- `tiles_api_key` is the only secret (the repo is public) — it lives in the
  gitignored `secrets.yml`. Everything else (`PLUVIO_*`) is public config; the
  forecast `cache` volume is regenerated by the worker, so nothing to migrate.

## Cutover

Validate first under `pluvio-hetz1.appmire.be` (set `pluvio_domain` in
`group_vars/all.yml`), then point `pluvio.appmire.be` DNS at the box, flip
`pluvio_domain` back, and run `site.yml --tags nginx` to issue the prod cert.
